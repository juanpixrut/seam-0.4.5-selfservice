### 2.4 Operating rules that cost something to learn

* Never use `sed`, `awk` or the built-in str_replace tool on repo files. Use
  `repoman ed` / `strreplace` (or a guarded Python read-modify-write).
* `cd <repo-root> && repoman ...` **in the same shell command**, every time;
  the working directory is not stable between tool calls.
* `repoman ed sub OLD NEW file --expect N`: flags go **after** the positionals.
  Before them they are swallowed as positionals and the command exits 0 having
  replaced nothing. `N` must come from a `repoman ed find` you just ran.
* Gate on the tool's own exit status. Do not pipe it through `grep`/`tail`; the
  pipe's status masks it. The shell here is `dash`: no brace expansion, no
  `PIPESTATUS`. Capture to a file, then read `$?`.
* Avoid `ed insert --before` (known to corrupt the matched span). Use
  `apply` or `sub`, and re-read the file after any edit with parentheses or
  quotes in it.
* `register add`: pass long bodies with `--body-file`; run `register check`
  after every add or close. `register close` needs a `## ` heading already in
  `docs/RESOLVED.md`. `register add/close` and `relcore`'s sync step do not
  record provenance, so the next `ed` on the same file may refuse; check the
  journal before treating that as a real outside edit.
* `.ed-journal.json` records the text of every edit. If an edit's text ever
  contains a forbidden string the journal will trip `badcode`; delete the
  journal (it is local state, never shipped).
* Mass substitution: classify every occurrence by syntactic role first. Last
  session's renames hit comments, object-literal keys, string literals
  (`'SelfLink'` type tags) and generated LaTeX (`\draw`) that a blanket regex
  had mangled; each was caught only by running the code.
* Keep sandbox-absolute paths and the forbidden strings out of repo files.

### 2.5 Verifying without a browser

Pure logic embedded in Go strings (such as the add/remove handlers) can be

## 3. Facts learned this session (reference)

* **OQL is T-SQL.** Row cap = `SELECT TOP n ...`; there is **no `LIMIT` and no
  `OFFSET`**. Paginate by fetching `TOP (limit+offset)` and slicing (see
  `internal/alerts/alerts.go`, `internal/auth/audit_store.go`,
  `internal/ui/routes.go`). `TOP` together with `ORDER BY` is already used in
  production code (alerts, the picker); that `ORDER BY` runs before `TOP` is
  assumed, not verified against a live xolu (T-95). `LIKE` is case-sensitive
  (per comments in the picker, confirmed there against a running instance).
  Escape user input with `escapeOQL`. `entityNotYetCreated(err)` turns "entity
  does not exist yet" into an empty result.
* **Sulpher** graph queries are a different language (Cypher-like, `MATCH ...
  LIMIT n`); `docs/modules/TRACKING.md:52` is one and was left alone.
* **Icons** are Material Icons ligatures from a self-hosted font
  (`web/static/vendor/fonts/MaterialIcons-Regular.woff2`), written as
  `<span class="material-icons">name</span>` or passed by name to
  `IconButton`, `EmptyState`, `ListPageConfig.CreateIcon` and similar. Valid
  names are in `web/static/vendor/material-icons-ligatures.txt`; `make
  check-icons` fails on unknown names but scans only `internal/ui`, so names
  used elsewhere (e.g. formengine) are not audited. No SVG icon set exists.
* **Formengine**: `x-seam-input` values map to renderers in `widgetRegistry`
  (`internal/formengine/widgets.go`, around line 62). `inferWidget` returns
  `f.XSeamInput` unchanged; there is no allowlist, an unknown name renders a
  "not implemented" placeholder. Tests render with `mi.RenderToString`;
  attribute text is HTML-escaped (`'` becomes `&#39;`). `jsStringLiteral`
  wraps in single quotes.
* **List component** (`internal/ui/listing.go`): composable primitives, not a
  column spec. `ListTableConfig{Columns []ListColumn{Label, Right}, EmptyIcon,
  EmptyTitle, EmptyMessage, SkipCard}` plus rows built by the caller with
  `ListRow(i, ListCell/ListCellMuted/ListCellRich/ListCellLink/ListCellRight/
  ListActions ...)`; `ListFilterBar` (a GET form), `ListPaginationBar` (needs a
  total), `ListPage`. `internal/ui/assets.go` (`AssetsListPage`) and
  `internal/ui/admin_users.go` (`UsersListPage`) show them composed.
* **Modal**: `SeamModal2.open(title, url, {maxWidth, anchorEl})`
  (`web/static/js/app.js`, around line 468) builds the dialog and loads `url`
  with `htmx.ajax('GET', url, {target:'#seam-modal2-body', swap:'innerHTML'})`;
  after the swap, any `[data-modal-footer]` content moves into the fixed
  footer. `SeamModal2.close()` closes it; an `seamModal2Saved` event on
  `document.body` also closes it.
* **Auth context**: `requireAuth` (`internal/ui/router.go`, around line 65)
  puts the session claims into the request context
  (`auth.ContextWithClaims`); `auth.TenantIDFromContext(ctx)` and
  `auth.UserFromContext(ctx)` read them (`internal/auth/auth.go`, around 546).
  `UIHandler` already holds `userService *auth.UserService` and
  `xoluClient *xolu.Client`.
* **i18n**: locale files are `internal/i18n/locales/{en,es,pt,ja}.json`.
  Formengine widget chrome goes through
  `resolveWidgetChrome(e, rc, "key", "fallback")`. I found no test that checks
  key parity across locales, so add every new key to all four files by hand.
* **Not in the repo**: two standalone HTML demos from earlier (a geometry check
  and a force-layout example for the FSM engine) lived outside it.

## 4. T-94 -- repeatable / document-links rows at zero items

**Report** (Work Orders): "x-seam-input: repeatable breaks when the item count
reaches zero; reproducible in the New Asset form, Service Configurations."

**Cause.** The add button's handler cloned the first remaining row
(`c.querySelector('.repeatable-row').cloneNode(true)`). The x button removes
rows with `.remove()`. With no rows left `querySelector` returns `null` and
the handler throws `Cannot read properties of null (reading 'cloneNode')`; the
button stays dead until reload. The server already copes with zero rows:
`parseAssetArrayField` (`internal/ui/asset_dynamic_post.go`) returns an empty
list exactly as for a single blank row. The same pattern existed in three
places: `renderRepeatable`, `renderDocumentLinks`, and the masters
document-links builder in `internal/ui/masters_pages.go`.

**Fix as written.** The remove handler stashes a clone of the row on the
container before removing it; the add handler uses the stash when no row is
left:

    remove:  (function(b){ var r=b.closest('.ROWCLASS'),c=r.parentNode;
               if(!c._rowTemplate){c._rowTemplate=r.cloneNode(true);} r.remove(); })(this)
    add:     var src=c._rowTemplate||c.querySelector('.ROWCLASS'); if(!src){return;}
             var t=src.cloneNode(true); ...reset inputs/selects...; c.appendChild(t);

`rowRemoveOnclick(rowClass string)` (in `repeatable.go`) builds the remove
handler for the two formengine widgets; `internal/ui/doclink_script.go` holds the
same text as a const for the `ui` package (the helper is unexported). The add
handlers are edited in place at the three sites.

### 4.1 To do
1. `go build ./... && go vet ./internal/formengine/... ./internal/ui/...`.
2. `go test ./internal/formengine/... ./internal/ui/...`. Changed tests:
   `TestRepeatable_RemoveButtonPerRow` (now counts `b.closest(&#39;.repeatable-row&#39;)`
   twice) and `TestDocumentLinks_RemoveButtonPresent`. New:
   `TestRepeatable_AddFallsBackToStashedTemplateAfterLastRowRemoved` and
   `TestDocumentLinks_AddFallsBackToStashedTemplateAfterLastRowRemoved`; they

3. Browser check: New Asset > Service Configurations. Remove all rows, add,
   add, remove one, add; submit with zero rows and confirm the asset saves with

4. Then close T-94 with `repoman register close T-94 --version <next>` and

### 6.2 Design (default; the user has not seen the code-level version)
* **Registry, server-side, in Go**, keyed by a short name (`users`,
  `assets`, ...), in a new `internal/ui/selector.go`:

      type SelectorRow struct { ID int64; Label string; Data map[string]any }
      type SelectorColumn struct { LabelKey string; Right bool
                                   Cell func(r SelectorRow, t func(string, ...any) string) mi.H }
      type SelectorSource struct {
          Key, TitleKey, EmptyTitleKey, EmptyMessageKey string
          Columns  []SelectorColumn
          PageSize int
          Fetch    func(ctx context.Context, h *UIHandler, q string, page, pageSize int) (rows []SelectorRow, hasMore bool, err error)
      }

  `Fetch` is a function, not a table+column pair, so the Users entry can go
  through `auth.UserService` (never `SELECT *` rows that carry password
  hashes) and so other entities can supply their own query.
* **Route**: `GET /selector/{key}` under `requireAuth`, next to
  `GET /picker/search` in `internal/ui/router.go` (around line 203). Query
  params: `q`, `page`, `target` (id of the opener's hidden input). Unknown key
  -> 400, as the picker does.
* **Rendering** reuses `ListTable`/`ListRow`/`ListCell*` with `SkipCard`,
  `ListFilterBar`-style search, and pagination. Caveat: `ListFilterBar` is a
  plain GET form and `Pagination` emits normal links; inside the modal they must
  swap into `#seam-modal2-body` instead of navigating, so give the search input
  `hx-get`, `hx-trigger="keyup changed delay:250ms"`, `hx-target="#seam-modal2-body"`
  and the pager links `hx-get`/`hx-target` (or wrap in `hx-boost`). `ListPaginationBar`
  needs a total; if no count is available use Prev/Next driven by `hasMore`
  (fetch `limit+1`). Whether OQL supports `COUNT(*)` is **unverified**.
* **Choosing**: each row carries `data-id` and `data-label`; a small JS helper
  (add to `web/static/js/app.js` beside `SeamModal2`) reads them with
  `textContent`/`dataset` (never `innerHTML`), dispatches
  `document.dispatchEvent(new CustomEvent('seam:selector-chosen', {detail:{key,id,label,target}}))`
  and calls `SeamModal2.close()`. The opener (the any-picker widget, section 7)
  sets its hidden input and visible label. Record labels must never be
  interpolated into inline script (the lesson of T-63/T-64).
* **Open it** with `SeamModal2.open(title, '/selector/users?target=' + id,
  {maxWidth:'720px'})`.
* **Users source**: `h.userService.ListUsers(ctx, auth.UserFilter{TenantID: t,
  Active: &true, Limit: pageSize+1, Offset: (page-1)*pageSize})`, tenant from
  `auth.TenantIDFromContext(ctx)`. `UserFilter` has **no search field** today:
  add `Search string` and, in `XOLUUserStore.ListUsers`, a condition on name /
  email using `escapeOQL` (same shape as the picker's `LIKE '%q%'`). Columns
  copy the admin list: name + email composite cell, role badge (`userRoleBadge`).
* **i18n**: add keys such as `selector.search.placeholder`, `selector.empty_title`,
  `selector.empty_message`, `selector.choose`, `selector.title.users` and the
  column labels to all four locale files.

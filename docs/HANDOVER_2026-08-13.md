## 3. Non-negotiable tooling conventions

These aren't preferences — deviating from them has caused real, silent
damage in this project's own history, which is why they're rules now.

### 3.1 Editing tools, in strict precedence order

1. **repoman** (`github.com/ha1tch/repoman`, vendored in-repo at
   `repoman/`) is the preferred tool whenever available. At the start
   of any editing session: check for in-repo copies first (this repo
   has them at `repoman/`), run the acceptance gate before first trust
   — `python3 repoman/ed.py selftest` (9 checks, all must pass) and/or
   `python3 selftest.py` if working from a fresh clone (18 checks).
   Use `ed.py` for substitutions/targeted edits, `register.py` for
   register operations (**read `docs/TRACKING.md` before assigning
   IDs** — the register itself is the source of truth for the next
   free ID, not any cached count), `guards.py` for dormant-guard
   currency, `syncver.py`, `relcore.py`.
2. Where `ed.py` genuinely can't express the edit: guarded Python —
   read the whole file, construct the change explicitly, verify
   line/content counts before writing, write atomically.
3. **`str_replace` is fine** for trivial single edits on files whose
   full content is already in your context — this session used it
   constantly for that case.
4. **`sed`/`awk`: never.** No exceptions, even for edits that look
   trivial. Line-by-line operation corrupts multiline strings, Unicode
   handling is platform-dependent.

### 3.2 Mass substitution — the rule that saved this session repeatedly

**Before any substitution touching more than one occurrence or one
file, classify every occurrence by syntactic role first.** The single
most valuable discipline this whole session relied on:

- If a target string means the same thing in every occurrence and
  needs the same treatment everywhere → a whole-file or whole-tree
  substitution is safe.
- If the same literal string means **different things** in different
  places (a genuine collision, not just theoretical) → you must scope
  the substitution to only the region where it means what you think it
  means, usually via function-boundary detection (find `def
  target_function(`, find the next top-level `def `, only substitute
  within that span).

**Real collisions this session actually hit, not hypothetical ones:**
`nombre`/`marca_id` were shared vocabulary between Modelo and Asset —
a naive whole-file substitution would have corrupted Asset's own,
separate, not-yet-renamed fields. `alerta_id` is used by both
`service_configs` (Asset's own field, in scope) and the unrelated
`alerts` runtime table (a different entity, correctly left alone) —
confirmed by checking which function each occurrence sat inside before
touching anything.

**Always run a whole-tree completion sweep as the first step of
declaring something done, not a post-failure remedy.** `grep -rn` for
the old term across the entire relevant directory tree, not just the
files you already touched. This session found real, live regressions
in files that were never touched during the original rename, purely
by doing this sweep (§6 has the specifics).

### 3.3 Testing and verification discipline

- **Build-driven iteration to find consumers**: after renaming a Go
  struct field or type, `go build ./...` and fix whatever the compiler
  points at, then rebuild, repeat. This reliably finds every real
  consumer — grep alone missed struct-literal call sites more than
  once this session.
- **A clean build does not mean nothing is wrong.** Go's static typing
  only catches compile-time mismatches. Runtime string keys (xolu
  storage keys, i18n keys, map keys) need actual execution to verify.
  This session found multiple real, live bugs (broken dashboard
  widgets, broken dropdown labels) that compiled cleanly and passed
  `go vet` but were genuinely broken until tested against a real
  server.
- **Sanity-check every fix, every time, no exceptions**: before
  trusting a new test (or an existing one you just updated), revert
  the actual fix, confirm the test genuinely fails for the right
  reason, then restore the fix and confirm it passes again. This
  session caught its own test-writing mistakes this way more than
  once (a "round-trip" test that passed even with the underlying logic
  completely broken, because it only checked internal consistency, not
  the actual external contract).
- **Live-verify user-facing changes in at least two locales**, English
  plus one other (Spanish, in this project). A change that "compiles
  and passes unit tests" is not verified until you've actually loaded
  the real page and read the actual rendered text. This session's
  single most valuable catch (§7) was found exactly this way — a unit
  test with a mock translator passed, but the *real* page, loaded in
  the *real* English locale, showed a genuinely broken sentence mixing
  two languages.
- **Never background a long-running command and poll it.** Run
  foreground, wait for the actual return.
- Never use shell brace expansion (`{a,b,c}`) — inconsistent shell
  support, produces silent garbage.

### 3.4 Version bump discipline

Prefer patch bumps by default (`0.3.84` → `0.3.85`). Reserve minor
bumps for genuine capability thresholds. When in doubt, patch.

### 3.5 The release process, exactly

Every piece of completed work this session went through this exact
sequence — follow it precisely, in order:

1. File the register entry: `python3 repoman/register.py add
   --summary "..." --theme "..." --priority Pn --blocks "..."
   --body-file /tmp/whatever.md` (write the body to a temp file first,
   it's almost always too long for an inline arg).
2. If the item represents completed work, close it in the same
   session: `python3 repoman/register.py close T-NN --version
   0.3.XX`. This moves the full text to `docs/RESOLVED.md`
   (append-only, newest first) and removes it from the open register
   in `docs/TRACKING.md`.
3. **Closed records in `RESOLVED.md` are append-only — never rewritten
   after the fact, even to fix a framing mistake you later notice.**
   If you need to correct something about a closed item, add a
   cross-reference note to a *different*, still-open item (or a new
   one) that explains the correction. This session did this exactly
   once, correcting sloppy language in a closed T-79 by adding a note
   to the still-open T-40 instead of editing T-79's own closed record.
4. Sync version headers across `docs/TRACKING.md`,
   `docs/KNOWN_ISSUES.md`, `docs/formengine/TRACKING.md`,
   `docs/modules/TRACKING.md` — a small Python regex substitution,
   confirm each file actually changed (not silently skipped).
5. Write the `CHANGELOG.md` entry — prepend before the first existing
   `## [` marker.
6. Run the full gate: `go build ./...`, `go test ./... -count=1`,
   `python3 repoman/register.py check`.
7. `./release.sh 0.3.XX` — this cuts a checkpoint zip, verifies
   VERSION/CHANGELOG consistency, checks for stray artifacts.
8. Copy the resulting `seam-vX.X.X-checkpoint.zip` and `.sha256` to
   `/mnt/user-data/outputs/` and call `present_files` on them.

This session did this **18 times** (v0.3.68 through v0.3.85). It
becomes fast once you've internalized it. Don't skip steps to save
time — the register's own integrity depends on every step happening
in order.

## 4. How to actually run and test this thing

```bash
source ~/goenv.sh
```

### 4.2 Starting a fresh test environment

```bash
# xolu, fresh data directory
rm -rf /tmp/xolu-data-fresh
mkdir -p /tmp/xolu-data-fresh
cd /tmp
XOLU_API_V2_ENABLED=true setsid /tmp/xolu-bin --port 9090 \
  --base-dir /tmp/xolu-data-fresh --no-ascii > /tmp/xolu.log 2>&1 < /dev/null &

# seam-ui, pointed at that xolu

  --xolu-url http://localhost:9090 > /tmp/seam.log 2>&1 < /dev/null &

```

**A note on flakiness**: `curl` against a just-started server
sometimes returns nothing on the first attempt even though the server
is genuinely up a moment later — this happened repeatedly this
session and is a sandbox/timing quirk, not a real failure. Retry once
with `--max-time 8` before concluding something is actually broken.

**A separate note**: this session's servers were killed by container
recycling multiple times mid-work, unpredictably. If a server that was
running a moment ago suddenly isn't responding, don't assume you broke
it — just restart both (xolu first, then seam-ui) and continue. xolu's
own data directory survives a restart (SQLite on disk), so you won't

### 4.4 Logging in and driving the UI via curl

```bash
cd /tmp
rm -f cookies.txt
curl -s -c cookies.txt http://localhost:8080/login -o login_page.html
python3 -c "
import re
html = open('login_page.html').read()
csrf = re.search(r'name=\"_csrf\"[^>]*value=\"([^\"]*)\"', html).group(1)
open('/tmp/login_csrf.sh','w').write(f'CSRF=\"{csrf}\"\n')
"
. /tmp/login_csrf.sh
curl -s -b cookies.txt -c cookies.txt -X POST http://localhost:8080/login \
  --data-urlencode "email=hl@example.com" \
  --data-urlencode "password=holaquetal" \
  --data-urlencode "_csrf=${CSRF}" -o /dev/null
```

Then use `-b /tmp/cookies.txt` on subsequent requests. For any
HTMX-driven form (most of them), add `-H "HX-Request: true"` when
fetching a form fragment — without it, several handlers deliberately
**redirect** rather than return the form (a genuine, tested behavior,
not a bug — this session tripped on it once before checking).

### 4.5 Switching locale for live verification

There is no query-param locale override — it's a genuine per-tenant
setting via the real settings form:

```bash

curl -s -b cookies.txt -c cookies.txt -X POST http://localhost:8080/settings/general \
  --data-urlencode "_csrf=${CSRF}" \
  --data-urlencode "tenant_name=Constructec S.A." \
  --data-urlencode "locale=en"   # or "es"
```

Four locale files exist and are kept in sync:
`internal/i18n/locales/{en,es,ja,pt}.json`. Whenever you add a new
i18n key, add it to **all four**, not just en/es — this project keeps
Japanese and Portuguese current too, confirmed by checking how every
existing comparable key is handled before assuming otherwise.

## 5. What just happened this session — the identifier campaign

This was the dominant thread of the entire session: **T-40**, a
project-wide rename of internal identifiers from Spanish to English,
per the tech team's own explicit, standing law (see §5.1). It started with
a paused audit from an earlier session and this session drove it to
full completion, plus a follow-up reverse-direction sweep. If you're
picking up anywhere near this area of the code, read this section in
full — it explains *why* the code looks the way it does now, not just
what changed.

### 5.1 The law, stated exactly (quote this back if anyone asks)

> **Internal = identifiers, invariants, constants, states — always
> English, no exception. External = user-facing text — depends on
> locale.**

This covers enum *values* used as stored/validation tokens too, not
just field/column names. But — and this distinction mattered
repeatedly — **enum values themselves are a separate axis from field
names**, and this project's own established precedent (confirmed
against Alerta, the first entity ever fully migrated) is: field
*names* go English; the stored *values* for enum-like fields
(criticality's "Alta"/"Media"/"Baja", tenure_type's "Propiedad" etc.)
**stay Spanish-stored**, translated at the boundary via a
value-translation table, not renamed. Don't conflate the two.

### 5.2 What's actually done now

**All eight masters entities**: Region, Moneda→Currency,
Marca→Brand, Ubicación→Location, Custodio→Custodian, Alerta,
Modelo→Model, and the two-part PropDefinition/PropAssociation. All
fully renamed — Go struct fields, xolu storage columns, seed script
keys, all live-verified end to end.

**Asset itself** — the big one, 32 real field renames across seven
logical blocks (matching the existing `// Block A-G` comments already
in `AssetDetail`'s own source):

- Block E (Lifecycle): `PurchaseDate`/`ExpectedArrivalDate`/
  `ArrivalDate`/`ObsolescenceDate`/`ExpirationDate`/
  `DecommissionDate`/`DecommissionReason`
- Block B (Characterisation): `BrandID`/`ModelID`/`Serial1`/`Serial2`/

- Block C (Location): `LocationID`/`RegionID`/`ParentID`

### 5.3 The critical, repeated lesson: identity map, not empty map

The single most important, most-repeated technical lesson from this
whole campaign, because **it was learned the hard way twice** in this
session before being applied correctly by rote the third time onward:

When a bridge map (e.g. `assetFieldToXolu`, translating between the
schema's English field names and xolu's stored column names) is fully
migrated so both sides are identical, **do not empty it to
`map[string]string{}`**. This project's shared translation function
(`translateFlatFieldsAndEnums`, `internal/ui/masters_xolu_fields.go`
and `internal/ui/asset_xolu_fields.go`) only applies **enum-value**
translation for a field when that field's own key is found in the
bridge map at all — a genuinely empty map silently skips value
translation entirely for every field, not just the renamed ones.

**The fix**: convert the bridge to an **explicit identity map**
(`"criticality": "criticality"`, not omitted) for every renamed field,
whether or not that specific field has an enum-value table. This
matches the pattern Alerta's own bridge already established the first
time this project ever did this kind of rename — check `alertaFieldToXolu` in
`internal/ui/masters_xolu_fields.go` as the canonical reference before
touching any other bridge map.

**Before touching any bridge map for a future rename**: check the
corresponding `*EnumValueToXolu` table for that field first. If it has
one, you need an identity map. If in doubt, use an identity map
anyway — it's never wrong, only occasionally unnecessary.

### 5.4 Real, live regressions found via dark-spot sweeps — read before assuming anything is "done"

**This is the most important operational lesson of the whole session**:
completing a rename and shipping it is not the same as it being fully
correct. Multiple real, live, user-facing bugs were found *after* a
block had already been released, purely by doing a deliberate sweep
for the same class of mistake in files the original rename never
touched:

- The assets dashboard's "urgency list" widget (a JSON config file,
  `internal/dashboardengine/schemas/assets-dashboard.json`) hardcoded
  a raw xolu column name (`fecha_expiracion`) directly — broken
  silently for three releases after that column was renamed, found
  only by a deliberate audit, not by any test.
- Two separate delete-protection `countRef` guards (Model, Currency,
  Cost Center) were missed during their own respective renames — found
  by sweeping every `countRef(ctx, "assets", ...)` call site after
  finding the *first* miss, not assumed to be isolated.
- A Model summary card handler (`internal/ui/summary_handlers.go`), in
  a file neither the Modelo rename nor any later pass ever touched,
  was still reading two stale xolu columns — the asset edit form's own
  Model dropdown had been rendering empty labels in every real
  deployment since the release that broke it.
- A separate, whole different Go module — `internal/ui/workflow/`
  (§6) — was discovered to be completely unbuildable and had been
  invisible to every test run this session (and probably several
  before it).

**Practical instruction for you**: after finishing any rename or
refactor, before calling it done, run a sweep for the exact same class
of mistake across files you didn't touch during the main work. Check
delete-protection guards, dashboard/widget JSON configs, summary
cards, and anything with its own separate `go.mod`. This isn't
optional diligence — it's how real, shipped bugs were found this
session, repeatedly.

### 5.5 Seed script substitution — the pattern and its one real miss

Every rename included updating all six seed scripts' Python data. Two
techniques, chosen by whether the target key is genuinely ambiguous at
file scope:

- **Whole-file substitution**, when the key is confirmed exclusive to
  one entity's own data (checked by grep before running, not assumed).
- **Function-boundary-scoped substitution** (`def target_function(` to
  the next top-level `def `), when the same literal key genuinely
  means different things in different places within the same file —
  e.g. `alerta_id` inside `seed_service_configs` (in scope) versus the
  very next function, `seed_runtime_alerts`, which has its own,
  unrelated `alerta_id` belonging to a different entity entirely.

**The one real miss, worth remembering**: a naive double-quote-only
substitution (`"old_key"` → `"new_key"`) missed a
**single-quoted f-string dict access** — `item['old_key']` inside a
Python f-string used for a print statement. This crashed a live seed
run. After that, every subsequent substitution explicitly checked for
both quote styles before trusting a "zero remaining occurrences"
result.

## 7. The reverse-direction i18n sweep — the mirror-image bug

After T-40 closed, we asked for a sweep for the *opposite*
violation of the same law (§5.1): hardcoded **English** user-facing
text bypassing the i18n system, rather than Spanish internal
identifiers. This produced **T-91**, closed, with two real findings
worth understanding before touching `internal/ui/assets.go` or
`internal/ui/listing.go` again.

### 7.1 What was found and fixed

`internal/ui/assets.go` was the **sole outlier** across the entire
`internal/ui` tree — nine strings (page title, empty-state title and
message, search placeholder, five filter-option labels) hardcoded
directly in English while every sibling field on the exact same struct
literals already correctly called `t(...)`. Confirmed via direct grep
across every comparable `Title:`/`EmptyTitle:`/`EmptyMessage:` literal
in the whole tree before concluding it was isolated.

Most of the needed i18n keys already existed (this was a wiring gap,
not missing infrastructure). Three genuinely new keys were added
across all four locales: `assets.empty_title`, `assets.empty_message`,
`assets.search_placeholder`.

**A real complication, worth knowing if you touch this function
again**: `assetsFilterBar`'s own type-filter loop used `t` as its own
local loop variable name (`for _, t := range data.AssetTypes`), which
would have shadowed the translator function parameter needed for the
fix. The loop variable was renamed (`at`) rather than working around
the shadow — keep the translator parameter named `t` everywhere, it's
this codebase's universal convention.

### 7.2 The deeper bug, found only by loading the real page

Fixing `assets.go`'s own `Label:` value for the pagination count line
made the *label* correct but not the *sentence*. Live-testing in
English revealed: **"Mostrando 16 de 16 Assets"** — the shared
`ListPaginationBar` component (`internal/ui/listing.go`) hardcoded its
entire count-line template in Spanish
(`fmt.Sprintf("Mostrando %d de %d %s", ...)`) regardless of locale,
completely independent of whatever label was passed to it.

**Fixed properly**: a new parameterized i18n key,
`pagination.showing` (`"Showing %d of %d %s"` / `"Mostrando %d de %d
%s"` / genuine constructions for ja/pt — confirmed the translator's
